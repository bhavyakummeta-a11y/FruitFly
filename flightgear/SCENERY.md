# Visible obstacle course for FlightGear

This optional scenery overlay adds three large **tornadoes** (dark funnels, the
same shape as the live obstacle tornadoes) to the FlightGear world. They are
deliberately oversized test markers (2,000 m high) and stand still: scenery
objects are static, so these funnels don't turn. The same centres, radii, and MSL base/top heights
are used by the Python controller and companion map. The funnel stays inside
the controller's cylinder: it is as wide as the cylinder at the top and narrows
towards the ground.

The bundled course is near San Francisco Bay, with origin **37.600000° N,
122.350000° W** and tornadoes north of that point. Keep normal terrain scenery
installed: this overlay contains objects only and does not replace terrain.
It does not automatically start the engine, configure trim, or enable native
FlightGear aircraft collision physics. The Python controller retains its own
collision/clearance checks.

## Enable it on your Mac

1. In FlightGear's launcher, add this directory to **Add-ons → Additional scenery
   folders**, keeping your existing scenery folders:

   ```text
   /Users/Bhavya_1/FruitFly/flightgear/obstacle-course
   ```

   Select the directory containing `Objects`, not `Objects` itself. On a different
   machine, use that checkout's absolute path. Remove this entry to uninstall.

2. Keep your existing Cessna UDP arguments and add these in **Settings → Additional
   Settings**. Set the launcher location consistently; remove conflicting old
   latitude/longitude/altitude arguments:

   ```text
   --lat=37.600000
   --lon=-122.350000
   --altitude=3000
   --heading=0
   --vc=100
   --in-air
   --prop:/sim/freeze/master=true
   --prop:/sim/rendering/static-lod/rough=20000
   --generic=socket,out,20,127.0.0.1,5501,udp,flybrain-state
   --generic=socket,in,20,127.0.0.1,5502,udp,flybrain-controls
   ```

   Each UDP argument should occur only once. Use daylight, clear visibility and
   calm weather. Restart FlightGear to load the scenery. Start with a running
   engine and stable trim as in the existing Cessna setup. The paused start keeps
   the plane from passing the first tornado while you launch the controller.

3. From the repository root, run:

   ```sh
   .venv/bin/python -m flight_simulator --backend flightgear --brain reflex --obstacles flightgear/obstacle-course/course.json --seconds 180 --no-runlog --log runs/cessna-scenery.csv
   ```

   The companion opens automatically. The controller resumes the paused flight.
   The first tornado is 1.3 km north of the starting point, directly ahead at heading
   000°. The other tornadoes are 3.3 km and 5.4 km north, offset sideways.

4. Once stable, replace `--brain reflex` with `--brain connectome` for neural
   escape decisions. That mode pauses between full-brain trials.

**Use the course.json argument every time.** Running without it uses the older
moving-origin virtual course, whose objects will not match this scenery. For the
fixed scenery course, the controller never rotates, rescales, or reanchors the
tornadoes at startup. Initial heading should be north so the airplane flies through
the course. Starting more than 20 km away fails with a location error.

## Troubleshooting

- No tornadoes: confirm the selected scenery folder contains `Objects`, restart
  FlightGear, check your starting coordinates, and check FlightGear's log for
  missing `.stg` or `.ac` files. Increase visibility and use the supplied static
  object range setting. This course uses FlightGear's classic STG object overlay.
- Different companion and cockpit obstacles: check that the controller uses the
  `course.json` in the exact scenery folder loaded by FlightGear. Do not edit
  model dimensions or STG positions independently.
- Aircraft turning/crashing: scenery adds visible objects, not additional flight
  stabilization. Save `runs/cessna-scenery.csv` to diagnose the actual aircraft.
- Bases below terrain: object bases are fixed at 0 m MSL. This course is intended
  for the bay test area, not terrain-following placement on arbitrary mountains.

## Reproduce or relocate

The overlay is already generated and included in the repository. To create a
separate course elsewhere (the output directory must not already exist):

```sh
python3 -m flight_simulator.scenery --output runs/my-scenery --latitude 37.60 --longitude -122.35
```

Use the new directory as the scenery folder and its `course.json` with the
controller. Set FlightGear's start latitude/longitude to the same origin.
The generator creates the AC3D meshes, tile paths/STG placements, and controller
JSON together. No downloaded models, textures or separate asset licenses are
required; the meshes are generated by this project's code.

## Verification and sources

Automated checks cover a documented FlightGear tile index, geographic coordinate
round trips, fixed-origin telemetry, model bounds/vertex references, and agreement
between scenery placements and controller geometry. Live FlightGear rendering
has **not** been verified on this development machine, which has no FlightGear
installation. The add-on is prepared for testing, not claimed visually confirmed
inside FlightGear.

Format references: [FlightGear object placement](https://wiki.flightgear.org/Howto:Place_3D_objects_with_the_UFO),
[SimGear tile indexing](https://github.com/FlightGear/simgear/blob/next/simgear/bucket/newbucket.cxx),
[STG reader](https://github.com/FlightGear/simgear/blob/next/simgear/scene/tgdb/ReaderWriterSTG.cxx),
and [AC3D coordinate conversion](https://github.com/FlightGear/simgear/blob/next/simgear/scene/model/ModelRegistry.cxx).
